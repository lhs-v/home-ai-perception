# Home AI — 청각 상황 인지 데모

홈캠 소리 4개만 듣고 상황을 인지한 뒤, 영상으로 확인하고, 하나의 상황으로 통합해
개입 여부를 판단하는 과정을 5막으로 보여주는 웹 데모.

## 실행

**저장소에는 영상이 없다.** 원본은 각 YouTube 업로더에게 저작권이 있어 포함하지 않았다.
clone 한 뒤 한 번만 받으면 된다.

```bash
npm run setup     # 영상 12개 내려받기 + 측정 (2~3분)
npm run dev
```

`npm run setup` 은 `references/sources.json` 에 기록된 출처에서 영상을 받아
지정된 구간으로 자르고, 코덱을 통일한 뒤, 온셋·게인·움직임을 잰다.
받지 못한 클립이 있으면(영상이 내려갔거나 지역 차단) 그 클립만 빠지고 나머지로 돈다.
영상이 4개 미만이면 데모가 검은 화면 대신 안내를 띄운다.

필요한 것: **Node 18+**, **Python 3.9+**, **ffmpeg**, **yt-dlp**

```bash
pip install yt-dlp
winget install Gyan.FFmpeg DenoLand.Deno   # macOS: brew install ffmpeg deno
```

(deno 는 yt-dlp 가 YouTube 포맷을 가져올 때 쓰는 JS 런타임이다. 없으면 403 이 날 수 있다.)

이후에는 `npm run dev` 만 하면 된다.

```bash
npm run dev
```

설치할 의존성은 없다 — Node 18 이상만 있으면 된다. 실행하면 접속할 주소를 직접 찍어준다.

```
  로컬      http://localhost:8777/
  네트워크  http://192.168.0.2:8777/   (이더넷)
```

기본으로 모든 인터페이스(`0.0.0.0`)에 바인딩하므로 **같은 네트워크의 다른 기기**
— 노트북, 태블릿, 폰 — 에서도 위 네트워크 주소로 열 수 있다.
Windows 방화벽이 처음 실행 때 물어보면 "개인 네트워크"를 허용해야 한다.

- 포트 변경: `PORT=8778 npm run dev`
- 이 기기에서만 열기: `HOST=localhost npm run dev`

> 인증이 없는 개발 서버이고 프로젝트 폴더를 그대로 서빙한다(폴더 밖으로는 나가지 못하게
> 막아 뒀다). 신뢰할 수 있는 네트워크에서만 띄울 것.

시작하면 클릭 한 번을 요구한다. 브라우저 자동재생 정책 때문에 AudioContext 를
사용자 제스처 없이 열 수 없어서다. **소리가 이 데모의 절반이므로 볼륨을 켜고 볼 것.**

## 구성

```
app/
  index.html          무대 전체의 DOM
  css/app.css         상태색·모션 규칙
  js/
    audio.js          4개 영상을 하나의 Web Audio 그래프로 묶는다
    ring.js           오디오 반응형 링 (파형·인지 모드·여무는 결 스윕)
    main.js           5막 연출 제어
    fusion.js         상황 융합 + 개입 판단 규칙엔진
  data/
    clips.json        클립 12개의 메타데이터 (온셋, 집중 구간, 재생 게인, 주석)
    fusion.json       시나리오 24개 + 판단 구간
    annotations.json  클립별 청각/시각/시맨틱 주석 원본
references/           클립 12개 (10~17초, H.264 + AAC)
tools/                수집·검증·분석 스크립트 (아래 참고)
```

## 다른 영상 넣기

### 운영자 탭 (권장)

```
http://localhost:8777/admin/
```

브라우저에서 끝난다 — mp4 를 끌어다 놓고, **인제스트 실행**을 누르고, 카드에서 주석을 채운 뒤
**변경사항 저장**. 클립마다 썸네일(오디오 온셋 지점)과 측정값(길이·온셋·게인·피크dB·움직임),
무음 여부, 주석 필요 여부가 함께 보인다. 삭제도 여기서 한다.

> 운영자 API 에는 **인증이 없다.** 서버가 0.0.0.0 에 바인딩되어 있으므로 같은 네트워크의
> 누구나 영상을 올리고 지울 수 있다. 쓰기가 가능한 경로는 `references/` 의 .mp4 와
> `app/data/clips.json` 둘뿐이고 파일명은 안전한 문자로 강제 변환되지만,
> 신뢰할 수 없는 망에서는 `ADMIN=off npm run dev` 로 끄거나 `HOST=localhost` 로 묶을 것.

### 명령줄

```bash
npm run ingest
```

기계가 잴 수 있는 것은 전부 자동으로 채워진다 — 코덱 정규화(H.264+AAC), 길이,
오디오 온셋, 1막에서 들려줄 집중 구간, 재생 게인, 무음 판정, 움직임 엔벨로프,
그리고 엔벨로프 모양에서 유도한 음향 질감.

기계가 못 정하는 것은 **자리표시자로 두고 `annotated: false` 를 단다.**

| 자동 | 사람이 써야 하는 것 |
|---|---|
| duration · onset · focus · gain · audible · motion · texture · loudness | title_ko · cue_line · description_ko · room · event_type · threat · tags |

주석이 없어도 **재생은 된다** — 링은 그 영상의 실제 소리와 움직임에 반응하고,
설명 자리에는 "아직 작성되지 않았다"고 정직하게 표시된다.
무슨 사건인지·얼마나 위험한지는 지어낼 수 없으므로, 온전히 연출되려면
`app/data/clips.json` 의 해당 항목을 채우고 `annotated` 를 지워야 한다.

이미 써둔 주석은 다시 돌려도 덮어쓰지 않는다. 측정값만 갱신된다.
(측정값까지 전부 다시 계산하려면 `npm run ingest:all`)

## 5막 구성

| 막 | 내용 | 길이 |
|---|---|---|
| 1 청취 | 검은 화면 + 링. 4개 소리가 **동시에** 울리고, 각 장치가 자기가 들은 것만 카드로 보고한다. 화면은 보이지 않는다 | 9초 |
| 2 전개 | 링이 감겨 돌며 물러나고 4분할 그리드가 펼쳐진다 | 1.3초 |
| 3 확인 | 네 영상이 같이 돌아가되 초점이 **하나씩** 옮겨가며 설명이 쓰인다 | 18초 |
| 4 통합 | 유휴 → 정지 → 연결 → 수렴 → 인지 → 발화. 네 장면이 링에 삼켜져 하나의 서술이 된다 | 20초 |
| 5 판단 | 서술이 링으로 녹아들고, 파형이 여물며 분석한 뒤 개입 여부를 내놓는다 | 10초 |

매 회차 12개 중 4개가 무작위로 뽑힌다. 사실상 무음인 3개는 풀에서 제외되므로
실제로는 9개 중 4개, 126가지 조합이다.

## 소리로만 알 수 있는 정보

1막의 큐 카드에는 **귀로만 알 수 있는 것**만 쓴다 — 음의 높낮이, 충격의 세기, 반복 패턴,
잔향, 거리감. 장소 이름이나 인물의 정체처럼 화면을 봐야 아는 정보는 넣지 않는다.
그래야 2막에서 "아, 저거였구나"가 성립한다.

## tools/

수집과 검증에 쓴 스크립트. 데모 실행에는 필요 없다.

| 파일 | 하는 일 |
|---|---|
| `dev-server.mjs` | 의존성 없는 정적 서버. Range 요청 지원(영상 탐색), 캐시 비활성 |
| `analyze_clips.py` | 오디오 RMS 엔벨로프·이벤트 온셋 추출, 대표 프레임 뽑기 |
| `validate_clips.py` | 정지화면·암전 검출 (freezedetect / blackdetect) |
| `scan_audio.py` | 클립별 실제 음량 측정 — 무음 감시영상을 걸러낸다 |
| `add_gain.py` | 피크와 평균을 함께 보고 클리핑 없이 체감 음량을 맞추는 게인 계산 |
| `hunt.py` / `hunt06*.py` | 교체 후보 대량 수집 + 자동 검증 |
| `swap_clips.py` | 검증 통과한 클립으로 교체하고 `clips.json` 재생성 |

Python 스크립트는 `yt-dlp`, `ffmpeg`, `deno`(yt-dlp 의 JS 런타임)를 쓴다.

## 알려진 한계

다섯 축(정확성·보안·구조·연출·데이터)으로 리뷰하고 각 지적을 반증 검증했다.
47건 중 41건이 검증을 통과했고, 심각한 것은 고쳤다. 남은 것은 아래와 같다.

**콘텐츠 편중**
- 뽑기 풀 9개 중 5개가 고위협이라 판단이 "즉시 개입"으로 쏠린다(126조합 중 77).
  클립을 더 넣어 저위협 쪽을 채우면 완화된다.
- `fusion.json` 의 시나리오 24개 중 14개는 현재 풀로 도달할 수 없다.
  `impact_fall` · `infant_distress` 를 요구하는 규칙이 특히 그렇다
  (10번 아기 울음이 `infant_distress` 인데 이를 매칭하는 시나리오가 없다).
- `theft_then_delivery` 의 서술이 재생 순서와 반대다 — `SEQUENCE` 는 `theft`(26)를
  `door_unlock`(18) 뒤에 두는데 서술은 "상자 소리 → 문 열림" 순으로 쓰여 있다.

**접근성**
- `prefers-reduced-motion` 은 지속시간만 줄인다. 4막 흡수 연출이 그 상태에서
  빈 시간이 된다. 이동 거리를 0으로 만드는 별도 경로가 필요하다.
- 보조 텍스트(`--text-3`) 대비가 3.4:1 로 WCAG AA(4.5:1)에 못 미친다.
- `#ring-status` 가 `aria-live` 인데 분석 구간에서 60ms 마다 갱신된다.

**도구**
- `tools/` 의 옛 수집 스크립트(`hunt*.py`, `validate_clips.py` 등)에는 ffmpeg 경로가
  하드코딩되어 있어 다른 PC 에서 그대로 돌지 않는다. `ingest.py` 는 PATH 에서 찾는다.
- 클립을 추가하면 움직임 공통 스케일이 다시 잡혀 **기존 클립의 `motion` 값이 전부 바뀐다.**
  의도된 동작이지만(상대 비교가 목적) 재현성이 필요하면 스케일을 고정해야 한다.

## 라이선스 주의

`references/` 의 원본은 각 YouTube 업로더에게 저작권이 있다. 개인 연구·모델 평가
용도로만 사용하고 재배포하지 말 것. 원본 URL 은 `references/index.json` 에 있다.
